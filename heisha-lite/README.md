# heisha-lite — 黑鲨冰封制冷背夹4Pro磁吸版（BR64）轻量控制 App

零第三方依赖的 Android 复刻实现。原 App（Shark Arsenal 5.6.1，186MB）中
只有 BLE 控制是背夹相关功能，其余是推送/统计/AI/PDF 等无关模块。


## 关键协议要点（踩坑总结，详见 ../docs/protocol-br64.md）

1. **查询前必须先握手**：`05 01 18 00 00` + `05 06 28 00 fa`，否则设备零响应
2. **命令不能连发**：间隔 <100ms 会被设备静默丢弃，初始化逐条隔 400ms
3. **连接只点一次**：重复点击会建多个 GATT client，导致 writeCharacteristic 全返回 false
4. **status=62 就重试**：设备有连接粘滞，App 重启后首次连接大概率失败

## 连接健壮性（2026-10-16 补充，针对"连接不上"实测定稿）

实机复现并修复了以下故障链，全部在 `CoolerBleManager` 内自动处理：

| 故障 | 现象 | 自动处理 |
|---|---|---|
| 设备端残留旧连接 | App 被杀/飞行模式切换后，背夹还认为连着，新连接全部 `status=62`（HCI Conn Failed to Establishment），实测可持续 6~8 分钟 | 失败后按 1.5s→12s 退避自动重试最多 36 次（约 7 分钟窗口）；仍失败则日志提示"给背夹断电重启 10 秒" |
| 断开回调丢失（僵尸连接） | 飞行模式切换后 Android 栈不上报 `onConnectionStateChange`，App 显示 READY 但写全部返回 false，永久卡死 | 写失败看门狗：连续 3 次写失败判定链路已死，强制 close() 旧 client 并重连 |
| 重复点击列表项 | 建多个 GATT client 互相抢占，之后所有写返回 false | 连接中/已连接时忽略重复点击 |
| 单次尝试无响应 | 一直卡在 CONNECTING | 单次尝试 12s 超时即放弃重试 |
| 重复的 MainActivity 实例 | 先用 adb/IDE 启动、再点桌面图标，会叠出第二个实例，各自持有一个 BLE manager；旧实例的连接一直占着背夹，背夹停止广播，新实例扫描不到 → "连接不上"，原版 App 却能按 MAC 秒连 | `singleTask` 启动模式 + `CoolerBleManager.get()` 进程单例 + 心跳放到 manager 内；扫描列表先加入系统中已连接/已配对的背夹（不依赖广播） |
| 退出 App 不断开 | `disconnect()`+`close()` 背靠背调用抢断优雅断开，设备端残留连接（status=62 的根源之一） | 先 `disconnect()`，收到 STATE_DISCONNECTED 回调后再 `close()`，1.5s 兜底 |

- 界面新增「断开」按钮：不杀 App 就能优雅断开，从源头避免设备端残留
- 重试进度写入 BLE 日志（`--- 1.5s 后重试（1/36）---`），用户能看到 App 在自动恢复
